## 1. 平台需要什么数据（数据格式）

### 1.1 数据存储方式

平台会将采集到的数据保存成一种标准格式（LeRobot Dataset格式），这种格式可以方便地进行数据分析和机器学习训练。

**简单理解**：
- 数据会保存成多个"数据片段"（episode）
- 每个片段包含一系列按时间顺序排列的"数据帧"（frame）
- 每一帧就是某个时刻机器人的完整状态

### 1.2 每一帧数据包含什么

每一帧数据包含三部分：

#### 1.2.1 机器人状态数据（观测数据）

**机械手/上肢部分**：
- **关节位置** (`hands.state`): 机械手每个关节当前的角度或位置
- **关节速度** (`hands.vel`): 机械手每个关节当前的移动速度
- **关节力矩** (`hands.torque`): 机械手每个关节当前受到的力
- **关节电流** (`hands.current`): 机械手每个关节当前的电流（可选）
- **目标位置** (`hands.action`): 想要达到的关节位置（来自遥控或控制器）

**腿部/底盘部分**：
- **关节位置** (`legs.state_q`): 腿部每个关节当前的角度或位置
- **关节速度** (`legs.state_qd`): 腿部每个关节当前的移动速度
- **关节力矩** (`legs.state_tau`): 腿部每个关节当前受到的力
- **目标位置** (`legs.cmd_q`): 想要达到的关节位置
- **目标速度** (`legs.cmd_qd`): 想要达到的关节速度
- **目标力矩** (`legs.cmd_tau`): 想要达到的关节力矩

#### 1.2.2 任务信息

- **任务模式** (`task_mode`): 当前正在执行什么任务（用数字表示，比如0表示待机，1表示抓取等）
- **任务描述** (`task`): 任务的文字描述（可选）

#### 1.2.3 时间信息

- **时间戳** (`timestamps`): 记录这一帧数据是什么时候采集的（精确到纳秒）
- **UTC时间** (`timestamps_utc`): 标准时间格式（例如："2025-01-31T10:30:45.123456+00:00"）

### 1.3 数据配置参数

在使用平台之前，需要告诉平台一些基本信息：

- **数据集名称** (`repo_id`): 给这个数据集起个名字，比如 "robot_001_demo_20250131"
- **采集频率** (`fps`): 每秒采集多少帧（默认30帧/秒）
- **机械手维度** (`hand_dim`): 机械手有多少个关节（默认30个）
- **腿部维度** (`leg_dim`): 腿部有多少个关节（默认12个）

### 1.4 数据保存位置

数据会保存在以下位置：
```
{LEROBOT_HOME}/{数据集名称}/
├── episode_0/           # 第1个数据片段
│   ├── data.parquet     # 实际数据
│   └── metadata.parquet # 元数据信息
├── episode_1/           # 第2个数据片段
│   └── ...
└── ...
```

## 2. 平台如何获取数据（数据来源）

### 2.1 数据来源说明

平台通过 **ROS2 话题（Topic）** 来获取数据。这是一个常见的机器人通信方式。

**简单理解**：
- ROS2话题就像是一个"广播频道"
- 设备端持续向这个频道"广播"数据
- 平台端"收听"这个频道，获取最新数据

### 2.2 平台需要订阅哪些话题

#### 2.2.1 必需的数据话题

**重要说明**：以下话题是功能必需的，缺少这些数据会导致采集的数据无法用于实际训练。

| 话题名称示例 | 数据类型 | 映射到内部字段 | 用途 | 更新频率要求 |
|------------|---------|---------------|------|------------|
| `/act_qpos`（或类似话题） | 浮点数数组 | `hands.action` | 获取机械手的目标位置（来自遥控或控制器） | 每秒至少10次（建议20-30次） |
| `/robot_joint_state`（或类似话题） | 浮点数数组 | `hands.state` | 获取机械手当前关节位置（当前状态） | 每秒至少20次（建议30次） |
| `/task_mode`（或类似话题） | 整数 | `task_mode` | 获取当前任务模式 | 每秒至少1次（或只在模式变化时更新） |

**注意**：
- 话题名称可以根据您的机器人系统自定义（只需在配置文件中正确映射）
- `hands.state` 和 `hands.action` 是训练模仿学习模型的核心数据对，两者都必需
- `/task_mode` 用于标记不同任务类型，也是必需的

#### 2.2.2 可选的数据话题

您可以根据机器人实际情况，配置更多话题来提供更多数据，例如：
- **机械手关节速度**（映射到 `hands.vel`）
- **机械手关节力矩**（映射到 `hands.torque`）
- **机械手关节电流**（映射到 `hands.current`）
- **腿部关节位置**（映射到 `legs.state_q`）
- **腿部关节速度**（映射到 `legs.state_qd`）
- **腿部关节力矩**（映射到 `legs.state_tau`）
- **腿部目标位置**（映射到 `legs.cmd_q`）
- 等等

**说明**：这些可选数据如果没有提供，平台会用零值填充，不会影响采集流程。

#### 2.2.3 配置话题映射

平台通过一个JSON配置文件来告诉它：哪些话题对应哪些数据字段。

**配置文件示例**（必需话题 + 可选话题）：
```json
{
  "repo_id": "robot_demo",
  "fps": 30,
  "hand_dim": 30,
  "leg_dim": 12,
  "ros2": {
    "enabled": true,
    "topics": [
      {
        "topic": "/act_qpos",
        "type": "Float32MultiArray",
        "target": "hands.action"
      },
      {
        "topic": "/robot_joint_state",
        "type": "Float32MultiArray",
        "target": "hands.state"
      },
      {
        "topic": "/task_mode",
        "type": "Int32",
        "target": "task_mode"
      },
      {
        "topic": "/robot_joint_velocity",
        "type": "Float32MultiArray",
        "target": "hands.vel"
      },
      {
        "topic": "/start_save_data",
        "type": "String",
        "target": "control"
      }
    ]
  }
}
```

**最小配置示例**（仅必需话题）：
```json
{
  "repo_id": "robot_demo_minimal",
  "fps": 30,
  "hand_dim": 30,
  "leg_dim": 12,
  "ros2": {
    "enabled": true,
    "topics": [
      {
        "topic": "/act_qpos",
        "type": "Float32MultiArray",
        "target": "hands.action"
      },
      {
        "topic": "/robot_joint_state",
        "type": "Float32MultiArray",
        "target": "hands.state"
      },
      {
        "topic": "/task_mode",
        "type": "Int32",
        "target": "task_mode"
      }
    ]
  }
}
```

**配置说明**：
- `topic`: ROS2话题的名称（必须完整路径，以`/`开头）
- `type`: 消息类型（支持三种：`Float32MultiArray`、`Int32`、`String`）
- `target`: 这个话题的数据在平台内部叫什么名字

### 2.3 数据采集流程

1. **数据缓存**：平台有一个"数据中心"，随时存储从各个话题收到的最新数据
2. **定时采样**：平台按照设定的频率（默认30次/秒），从这个数据中心读取最新值
3. **保存数据**：读取的数据会被格式化成标准格式，保存到数据集中

### 2.4 数据完整性说明

- **必需数据**：从功能角度看，以下数据是必需的（用于机器学习训练）：
  - `hands.state`（当前状态）- 机械手当前关节位置，用于记录机器人执行任务时的实际状态
  - `hands.action`（动作指令）- 机械手目标位置，用于记录控制指令，这是训练模仿学习模型的核心数据
  - 如果这两者缺失，虽然平台会用零值填充，但采集的数据无法用于实际训练
- **可选数据**：其他数据（速度、力矩、电流、腿部数据等）如果没有，平台会用零值填充
- **自动处理**：如果设备提供的数据数量（维度）与配置不一致，平台会自动调整（少了补零，多了截断）
- **容错机制**：如果某个话题暂时没有数据，平台会使用上次的值或零值

## 3. 设备需要提供什么数据（数据要求）

### 3.1 基本要求

设备端需要通过 **ROS2** 向指定的话题发布数据。只要您的机器人系统支持ROS2，就可以接入平台。

### 3.2 通讯协议说明

#### 3.2.1 ROS2协议概述

**ROS2（Robot Operating System 2）** 是一种机器人软件框架，提供了标准化的通信机制。

**关键概念**：
- **节点（Node）**：ROS2中的基本执行单元，您的设备需要创建一个或多个节点
- **话题（Topic）**：数据发布的"频道"，每个话题有一个名称（例如：`/act_qpos`）
- **消息（Message）**：在话题上传输的数据包
- **发布者（Publisher）**：向话题发送数据的节点
- **订阅者（Subscriber）**：从话题接收数据的节点（平台端充当订阅者）

**简单理解**：
- 设备端创建"发布者"，向话题发送数据（类似广播）
- 平台端创建"订阅者"，从话题接收数据（类似收听广播）

#### 3.2.2 ROS2版本要求

- **推荐版本**：ROS2 Foxy、Galactic、Humble 或更新版本
- **DDS中间件**：支持 Fast DDS、Cyclone DDS 等主流DDS实现
- **网络要求**：设备端和平台端需要在同一网络（或配置跨网络通信）

#### 3.2.3 话题命名规范

**话题名称格式**：
- 必须以 `/` 开头，例如：`/act_qpos`、`/robot/joint_state`
- 可以使用 `/` 分隔单词，形成层次结构，例如：`/robot/arm/joint_state`
- 建议使用有意义的名称，便于理解和调试

**命名建议**：
- 使用小写字母
- 单词之间用下划线 `_` 或斜杠 `/` 分隔
- 避免使用特殊字符

#### 3.2.4 消息类型规范

平台仅支持以下三种标准ROS2消息类型：

1. **`std_msgs/msg/Float32MultiArray`**
   - 用于传输浮点数数组（如关节位置、速度、力矩等）
   - 这是最常用的消息类型

2. **`std_msgs/msg/Int32`**
   - 用于传输单个整数值（如任务模式）
   - 数据范围：-2,147,483,648 到 2,147,483,647

3. **`std_msgs/msg/String`**
   - 用于传输文本字符串（如控制命令）
   - 长度不限，但建议不超过1024字符

**注意**：不支持自定义消息类型，必须使用上述三种标准类型。

### 3.3 数据内容参考

本节详细说明每个数据字段的含义、格式和使用场景。

#### 3.3.1 机械手/上肢数据字段

##### `hands.state` - 关节位置

**说明**：机械手/上肢各个关节的当前位置（角度或位置值）

**数据类型**：`Float32MultiArray`  
**数据单位**：通常为弧度（rad）或米（m），具体取决于关节类型  
**数据维度**：等于配置中的 `hand_dim`  
**更新频率建议**：20-30 Hz（匹配采集频率）

**重要性**：这是**功能必需字段**，必须提供！`state` 和 `action` 是模仿学习训练的核心数据对。

**示例数据**：
```python
# 30个关节的位置值（单位：弧度）
joint_positions = [
    0.0,      # 关节1：0度
    0.523,    # 关节2：30度（约0.523弧度）
    1.047,    # 关节3：60度（约1.047弧度）
    ...       # 其他关节
]
```

**应用场景**：
- 记录机器人在执行任务时各个关节的实际状态
- 与 `hands.action` 配对，形成"状态-动作"数据对，用于训练模仿学习模型

##### `hands.vel` - 关节速度

**说明**：机械手/上肢各个关节的当前移动速度

**数据类型**：`Float32MultiArray`  
**数据单位**：通常为弧度/秒（rad/s）或米/秒（m/s）  
**数据维度**：等于配置中的 `hand_dim`  
**更新频率建议**：20-30 Hz

**示例数据**：
```python
# 30个关节的速度值（单位：rad/s）
joint_velocities = [
    0.1,    # 关节1：0.1 rad/s
    -0.2,   # 关节2：-0.2 rad/s（负号表示反向）
    0.0,    # 关节3：静止
    ...     # 其他关节
]
```

##### `hands.torque` - 关节力矩

**说明**：机械手/上肢各个关节当前受到的力矩（力）

**数据类型**：`Float32MultiArray`  
**数据单位**：通常为牛顿·米（N·m）  
**数据维度**：等于配置中的 `hand_dim`  
**更新频率建议**：20-30 Hz

**示例数据**：
```python
# 30个关节的力矩值（单位：N·m）
joint_torques = [
    1.5,    # 关节1：1.5 N·m
    -2.3,   # 关节2：-2.3 N·m
    0.0,    # 关节3：无负载
    ...     # 其他关节
]
```

**备选**：如果设备无法提供力矩值，可以提供 `hands.current`（关节电流），平台会自动映射。

##### `hands.current` - 关节电流

**说明**：机械手/上肢各个关节电机当前的电流值（可选）

**数据类型**：`Float32MultiArray`  
**数据单位**：安培（A）  
**数据维度**：等于配置中的 `hand_dim`  
**更新频率建议**：20-30 Hz

**使用场景**：当设备无法直接提供力矩值时，可以用电流值替代

##### `hands.action` - 目标位置（动作指令）

**说明**：机械手/上肢想要达到的目标关节位置（来自遥控、控制器或规划器）

**数据类型**：`Float32MultiArray`  
**数据单位**：通常为弧度（rad）或米（m）  
**数据维度**：等于配置中的 `hand_dim`  
**更新频率建议**：≥10 Hz（建议20-30 Hz）

**示例数据**：
```python
# 30个关节的目标位置值（单位：弧度）
target_positions = [
    0.5,    # 关节1：目标位置0.5 rad
    1.0,    # 关节2：目标位置1.0 rad
    0.0,    # 关节3：目标位置0.0 rad
    ...     # 其他关节
]
```

**应用场景**：记录机器人的控制指令，用于训练模仿学习模型

**重要性**：这是**功能必需字段**，必须提供！没有这个字段，采集的数据无法用于模仿学习训练。

#### 3.3.2 腿部/底盘数据字段

##### `legs.state_q` - 腿部关节位置

**说明**：腿部/底盘各个关节的当前位置

    0.3,    # 左前腿关节2
    0.6,    # 左前腿关节3

##### `legs.state_qd` - 腿部关节速度

**说明**：腿部/底盘各个关节的当前移动速度

**数据类型**：`Float32MultiArray`  
**数据单位**：弧度/秒（rad/s）  
**数据维度**：等于配置中的 `leg_dim`  
**更新频率建议**：20-30 Hz

##### `legs.state_tau` - 腿部关节力矩

**说明**：腿部/底盘各个关节当前受到的力矩

**数据类型**：`Float32MultiArray`  
**数据单位**：牛顿·米（N·m）  
**数据维度**：等于配置中的 `leg_dim`  
**更新频率建议**：20-30 Hz

##### `legs.cmd_q` - 腿部目标位置

**说明**：腿部/底盘想要达到的目标关节位置

**数据类型**：`Float32MultiArray`  
**数据单位**：弧度（rad）  
**数据维度**：等于配置中的 `leg_dim`  
**更新频率建议**：20-30 Hz

##### `legs.cmd_qd` - 腿部目标速度

**说明**：腿部/底盘想要达到的目标关节速度

**数据类型**：`Float32MultiArray`  
**数据单位**：弧度/秒（rad/s）  
**数据维度**：等于配置中的 `leg_dim`  
**更新频率建议**：20-30 Hz

##### `legs.cmd_tau` - 腿部目标力矩

**说明**：腿部/底盘想要达到的目标关节力矩

**数据类型**：`Float32MultiArray`  
**数据单位**：牛顿·米（N·m）  
**数据维度**：等于配置中的 `leg_dim`  
**更新频率建议**：20-30 Hz

#### 3.3.3 任务信息字段

##### `task_mode` - 任务模式标识

**说明**：当前执行的任务模式，用整数标识

**数据类型**：`Int32`  
**数据范围**：-2,147,483,648 到 2,147,483,647  
**推荐范围**：0-100（足够覆盖大多数任务场景）  
**更新频率建议**：1-10 Hz（或只在模式变化时更新）

**任务模式定义建议**：
```python
# 任务模式定义示例
TASK_MODE_IDLE = 0        # 空闲/待机
TASK_MODE_GRASP = 1       # 抓取任务
TASK_MODE_PLACE = 2       # 放置任务
TASK_MODE_MOVE = 3        # 移动任务
TASK_MODE_CUSTOM_1 = 10   # 自定义任务1
TASK_MODE_CUSTOM_2 = 11   # 自定义任务2
# ... 可根据实际情况扩展
```

**应用场景**：
- 区分不同任务类型的数据
- 便于后续按任务类型筛选和分析数据
- 用于训练特定任务的模型

### 3.5 ROS2消息格式要求

平台支持三种标准的ROS2消息类型：

#### 3.5.1 浮点数数组消息（Float32MultiArray）

用于传输关节位置、速度、力矩等数组数据。

**Python发布示例**：
```python
from std_msgs.msg import Float32MultiArray
import rclpy
from rclpy.node import Node

class RobotPublisher(Node):
    def __init__(self):
        super().__init__('robot_publisher')
        # 创建发布器，话题名为 /act_qpos
        self.pub = self.create_publisher(Float32MultiArray, '/act_qpos', 10)
    
    def publish_joint_positions(self, positions):
        """
        发布关节位置数据
        positions: 一个包含浮点数的列表，例如 [0.1, 0.2, 0.3, ...]
        """
        msg = Float32MultiArray()
        msg.data = positions  # 直接赋值列表
        self.pub.publish(msg)

# 使用示例
if __name__ == '__main__':
    rclpy.init()
    node = RobotPublisher()
    
    # 假设机械手有30个关节
    joint_positions = [0.0] * 30  # 30个关节的位置值
    node.publish_joint_positions(joint_positions)
    
    rclpy.spin(node)
```

**发布频率建议**：
- 动作数据（目标位置）：每秒至少10次，建议20-30次
- 状态数据（当前位置、速度等）：建议匹配采集频率（默认30次/秒）

#### 3.5.2 整数消息（Int32）

用于传输任务模式等整数数据。

**Python发布示例**：
```python
from std_msgs.msg import Int32

class TaskModePublisher(Node):
    def __init__(self):
        super().__init__('task_mode_publisher')
        self.pub = self.create_publisher(Int32, '/task_mode', 10)
    
    def publish_mode(self, mode):
        """
        发布任务模式
        mode: 一个整数，例如 0表示待机，1表示抓取任务
        """
        msg = Int32()
        msg.data = mode
        self.pub.publish(msg)
```

#### 3.5.3 字符串消息（String）

用于传输控制命令（见第4节）。

**Python发布示例**：
```python
from std_msgs.msg import String

class ControlPublisher(Node):
    def __init__(self):
        super().__init__('control_publisher')
        self.pub = self.create_publisher(String, '/start_save_data', 10)
    
    def publish_command(self, command):
        """
        发布控制命令
        command: 字符串，例如 "start:session_001:1706695200.0:1800" 或 "stop"
        """
        msg = String()
        msg.data = command
        self.pub.publish(msg)
```

### 3.6 数据维度配置

    设备端需要告诉平台，数据数组的大小是多少。

**配置文件中的维度设置**：
```json
{
  "hand_dim": 30,  // 机械手相关数据数组的大小（例如30个关节）
  "leg_dim": 12   // 腿部相关数据数组的大小（例如12个关节）
}
```

**维度处理规则**：
- **数据太少**：如果设备发布的数据数量小于配置的维度，平台会自动用0填充
- **数据太多**：如果设备发布的数据数量大于配置的维度，平台会自动截断到配置的维度
- **建议**：在配置文件中准确设置维度，避免自动处理导致的数据丢失

### 3.7 数据同步说明

- **时间戳**：平台会自动为每一帧数据生成时间戳，设备端不需要提供
- **实时性**：平台会按照设定频率（默认30次/秒）采样最新数据
- **延迟容忍**：平台可以容忍小于一个采样周期（约0.03秒）的数据延迟
- **缺失处理**：如果某个话题暂时没有新数据，平台会使用上次的值或零值

## 4. 设备如何控制采集（控制接口）

### 4.1 控制命令说明

平台可以通过ROS2话题接收控制命令，实现程序化的采集控制。

**控制话题**：`/start_save_data`（可在配置文件中自定义）

### 4.2 支持的控制命令

#### 4.2.1 开始采集命令

**命令格式**：
```
start:会话ID:开始时间:目标帧数
```

**参数说明**：
- `会话ID`：给这次采集起个名字（字符串，可选）
- `开始时间`：什么时候开始采集（Unix时间戳，秒为单位）
- `目标帧数`：采集多少帧后停止（整数）

**示例**：
```
start:session_001:1706695200.0:1800
```
这表示：在时间戳1706695200.0时开始采集，采集1800帧后自动停止。

**说明**：
- 平台会在指定时间开始采集
- 达到目标帧数后会自动停止采集（但不会自动保存，需要手动触发保存）

#### 4.2.2 停止并保存命令

**命令格式**：
```
stop
```

**说明**：
- 平台收到该命令后，立即停止当前采集
- 自动将已采集的数据保存为一个新的数据片段（episode）

### 4.3 三种采集控制方式

#### 方式1：图形界面手动控制（最简单）

- 用户在平台的图形界面中点击"开始采集"按钮开始采集
- 点击"结束并保存"按钮停止采集并保存
- **优点**：简单直观，不需要编程
- **适用场景**：日常数据采集

#### 方式2：程序自动控制

- 设备端通过发布ROS2消息发送控制命令
- 发送`start`命令启动采集
- 发送`stop`命令停止并保存
- **优点**：可以实现自动化采集流程
- **适用场景**：需要批量采集、定时采集等场景

#### 方式3：混合控制

- 设备可以发送`start`命令触发采集
- 用户可以随时在图形界面中手动停止和保存
- **优点**：灵活，既可以自动化，也可以人工干预
- **适用场景**：需要自动化触发，但需要人工确认和停止的场景

### 4.4 任务模式管理建议

设备端可以通过发布任务模式来标记不同的采集场景。

**建议的任务模式定义**：
- `0`：空闲/待机
- `1`：采集模式A（例如：抓取任务）
- `2`：采集模式B（例如：放置任务）
- `3`：采集模式C（例如：移动任务）
- ...（可根据实际情况自定义）

**使用场景**：
- 区分不同任务的数据，便于后续分析
- 在数据集中自动标记任务类型
- 方便按任务类型筛选和训练模型

### 4.5 设备状态发布建议

设备端应该持续发布以下状态数据：

1. **机械手状态数据**（通过ROS2话题）
   - 关节位置、速度、力矩等
   - 建议更新频率：20-30次/秒

2. **动作指令数据**（通过ROS2话题 `/act_qpos`）
   - 来自遥控设备或控制器的目标位置
   - 建议更新频率：20-30次/秒

3. **任务模式数据**（通过ROS2话题 `/task_mode`）
   - 当前任务模式标识
   - 建议更新频率：1-10次/秒（或只在模式变化时更新）

### 4.6 错误处理建议

#### 数据缺失时的处理

- 如果设备暂时无法提供某个数据，可以停止发布该话题
- 平台会自动用零值或上次的值填充，不会中断采集

#### 连接断开时的处理

- 如果设备断开连接，平台会继续用上次的值填充数据
- 设备重新连接后，恢复数据发布，平台会自动恢复数据采集
- 不会丢失已采集的数据

#### 数据异常时的处理

- 建议设备在发布数据前进行合理性检查（例如：关节角度是否在正常范围内）
- 异常数据可能导致采集的数据质量下降

5. 采集的数据被格式化后保存为标准数据集

## 7. 常见问题解答

### Q1: 我的机器人没有ROS2接口，怎么办？

**A**: 需要先为机器人添加ROS2接口。这是接入平台的前提条件。如果您的机器人使用的是其他通信协议（如DDS、自定义协议等），需要先将其转换为ROS2话题。

### Q2: 如果数据维度与配置不匹配怎么办？

**A**: 平台会自动处理：
- 如果数据数量少于配置维度，平台会自动用0填充
- 如果数据数量多于配置维度，平台会自动截断

但建议在配置文件中准确设置维度，避免数据丢失。

### Q3: 平台支持实时控制机器人吗？

**A**: 当前版本主要专注于数据采集功能，不包含实时控制回环。但您可以通过ROS2话题向设备发送控制命令（这取决于您的机器人系统是否支持）。

### Q4: 如何验证数据是否正确采集？

**A**: 有以下几种方法：
- 查看平台终端输出的调试信息（会显示数据总和、维度等信息）
- 采集完成后检查生成的parquet文件
- 使用LeRobot提供的数据可视化工具查看数据集

### Q5: 采集的数据在哪里？

**A**: 数据保存在 `{LEROBOT_HOME}/{数据集名称}/` 目录下。`LEROBOT_HOME` 的默认位置通常是 `~/.cache/huggingface/hub/` 或项目指定目录。

### Q6: 可以同时采集多个机器人的数据吗？

**A**: 可以。每个机器人使用独立的配置文件，运行独立的采集实例即可。每个实例会保存到不同的数据集中。

**1. 结构化数据（data.parquet）**

每一帧包含的数据字段：

| 字段路径 | 数据类型 | 说明 |

| `observation.hands.state` | float32[] | 机械手关节位置（必需） |

| `observation.legs.state_tau` | float32[] | 腿部关节力矩（可选） |

## 8. 术语表

为了方便理解，这里解释一些常用术语：

- **ROS2话题（Topic）**：机器人系统中用于数据传输的"广播频道"
- **消息（Message）**：在话题上传输的数据包
- **话题订阅**：监听某个话题，接收该话题上的数据
- **话题发布**：向某个话题发送数据
- **数据帧（Frame）**：某个时刻机器人的完整状态
- **数据片段（Episode）**：一次完整的采集过程产生的所有数据帧
- **维度（Dimension）**：数据数组的大小，例如30表示数组有30个数字
- **采样频率（FPS）**：每秒采集多少帧数据
- **时间戳（Timestamp）**：记录某个数据是什么时候采集的
